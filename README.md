## 사용 순서

- **개요**: 주입 대상 수·검토 대기·종류별 기록·**기억 점검**·최근 기억을 확인합니다. ‘주입 대상 보기’는 저장 상태 기준이며 실제 생성 시 근거·분기 검증으로 줄어들 수 있습니다. ‘최근 답변’ 줄에 이 채팅의 마지막 답변에 기억을 몇 개 넣었는지, 또는 넣지 못했는지를 표시합니다.
- **종류별 탭**: 약속 → 진행 흐름 → 기억 앵커 → 장면 기억 → 요소 기억 → 이야기 위키. 목록에서 상세를 읽고 **편집**하거나 **직접 추가**합니다. 제목·내용·종류·공개 범위를 일반 입력칸으로 수정합니다. 진행·완료·취소 상태는 약속과 진행 흐름에만 표시합니다. 다른 종류에 남아 있는 이전 제외 상태는 자동 재개하지 않습니다.
- **분석**: 상단의 **분석** 버튼(또는 종류별 탭의 ‘원문에서 정리’)으로 엽니다. 메시지를 하나씩 불러오지 않고 번호로 고릅니다. **최근**(최근 N개, 기본 20) 또는 **범위**(`시작 – 끝`을 여러 줄, **+ 범위 추가**·**×**로 추가·삭제)를 고르면 ‘대화 120–141 (22개)’처럼 요약 한 줄만 보여 줍니다. 번호는 전체 채팅 순서 기준이고, **숨김 메시지도 같은 번호로 세어 함께 분석합니다**(요약 줄에 ‘대화 120–141 (22개, 숨김 5개 포함)’처럼 표시). 다른 확장이 정리한 메시지를 숨겼거나 컨텍스트를 아끼려고 옛 대화를 숨긴 채팅도 보관함에 넣을 수 있게 하기 위해서입니다. 숨긴 메시지에 비밀이 있다면 그 번호를 범위에서 빼세요. **+ 범위 추가**는 마지막 줄 바로 다음 번호부터 같은 길이로 새 줄을 채웁니다(예: 10–20 다음은 21–31, 채팅 끝을 넘으면 끝까지). 마지막 줄이 이미 채팅 끝까지면 이어서 추가할 범위가 없어 버튼이 꺼집니다. 범위는 채팅 길이에 맞춰 자르고 서로 겹치면 하나로 합치며(이어지기만 하는 10–20과 21–30은 합치지 않음), 정수가 아니거나 시작이 끝보다 크거나 채팅 밖인 범위는 이유를 알려 주고 분석하지 않습니다. 개수·번호 칸에 `1.5`, `-1`, `1e1`, `15abc`처럼 정수가 아닌 값을 넣으면 다른 숫자로 고치지 않고 입력한 그대로 둔 채 오류를 보여 주며 분석 버튼이 꺼집니다(서버도 같은 값을 거절합니다). 패널은 메시지 본문 없이 전체 개수와 숨김 위치만 처음 한 번 받아 두고(‘대화 개수 새로고침’으로 다시 받기), 본문은 **분석**을 누를 때 서버가 호스트에서 읽어 고른 번호의 본문만 모델에 보냅니다. **분석**을 한 번 누르면 바로 모델을 호출하고, 결과는 검토 대기 후보로만 들어갑니다(자동 승인 없음). 범위가 여러 개면 **범위마다 따로, 순서대로** 한 번씩 호출하고(‘범위 1/2 분석 중…’), 후보마다 어느 범위에서 나왔는지 출처에 남깁니다. 한 범위가 실패해도 나머지는 계속 분석하며, 끝나면 ‘2개 범위 중 1개 성공, 실패: 범위 2 (대화 21–30) – 이유’처럼 알려 줍니다. 분석하는 동안에는 분석 버튼이 꺼져 중복 실행되지 않습니다. 최근 N개는 한 번만 호출합니다. 한 번 호출에 보낼 수 있는 입력은 60,000자까지이며, 한 범위가 넘으면 그 범위만 호출하지 않고 더 작은 범위로 나누라고 안내합니다. 고른 방식·범위는 채팅별로 패널에 유지됩니다(페이지를 새로 불러오면 초기화).
- **후보 검토**: 분석 후보는 모두 ‘알 수 없음’ 범위로 들어오고, **승인할 때 사람이 공개 여부를 정합니다.** 개요의 검토 대기에서 후보를 펼쳐 **승인 · 프롬프트에 넣기**를 누르면 ‘모두가 아는 기억’으로 저장되어 다음 답변부터 프롬프트에 들어갑니다. 넣고 싶지 않으면 **비공개로 보관**을 누릅니다(저장만 하고 넣지 않음). 여러 개는 체크한 뒤 **선택 승인**·**선택 비공개로 보관**으로 한 번에 처리합니다. **전체 선택 (위험 후보 제외)** 는 지금 보이는 후보(종류 칩·검색 반영) 중 기존 항목을 바꾸는 후보·보류·근거 재검토·비밀/인물 제한·중복 의심·완료/취소 상태 후보를 빼고 고르며, 뺀 개수를 알려 줍니다. 이런 후보는 직접 골라도 일괄 승인에서 빠지므로 하나씩 열어 승인하세요. 비밀·인물 제한 후보는 공개로 승인할 수 없습니다. 직접 편집에서 새 공개 기억을 만들거나 제한을 풀 때는 지금처럼 **공개 범위 확대 확인**이 필요합니다.
- **이미 승인한 비공개 기억**: 이전 버전에서 승인해 ‘비공개 (주입 안 함)’로 남은 기억은 펼쳐서 **모두가 아는 기억으로 (주입)** 을 누르면 다음 답변부터 들어갑니다. 개요의 기억 점검에 그런 기억의 개수가 표시됩니다.
- **목록 보기**: 기억·검토 대기 후보 목록은 한 줄 요약으로 접혀 있고, 누른 항목만 펼쳐 본문과 편집·승인·삭제를 보여 줍니다. 한 번에 20개씩 표시하고 **더 보기**로 20개씩 늘리며, 종류 칩·검색으로 좁힙니다. 패널은 안쪽 스크롤 상자 없이 화면 스크롤 하나로 움직입니다.
- **일괄 처리**: 종류별 탭마다 **전체 선택 (N개)**·**선택 해제**·**선택 보류**·**선택 삭제**가 있습니다. 전체 선택은 그 탭에서 지금 필터·검색에 맞는 항목만(아직 펼치지 않은 페이지 포함) 고르고, 다른 탭으로 옮기면 선택이 풀립니다. 삭제는 개수를 보여 주는 확인 창을 거치며, 설정 탭의 되돌리기로 되살릴 수 있습니다. 확인 창을 연 뒤 다른 채팅으로 옮기거나 그 채팅의 기억이 바뀌면 확인을 눌러도 삭제하지 않으니 다시 골라 삭제하세요. 서버도 그 채팅에 없는 항목이 섞인 삭제 요청은 통째로 거절합니다. 보관(archive) 상태는 따로 없고, 보류가 주입을 멈추는 역할을 합니다.
- **설정**: 분석 모드(raw/quiet)와 모델 연결을 고릅니다. 분석 화면에는 모델 선택이 없고 여기서 고른 연결을 씁니다. **분석을 누르면 고른 범위의 원문이 이 연결로 바로 전송되므로, 비밀이 담긴 대화는 범위에서 빼세요.** **루미버스 요약(Loom) 참고**(선택, 기본 꺼짐, 아래 참고)와 **자동 분석**도 여기서 정합니다. 그 밖에 용량·실제 남은 undo 횟수·근거 재검토·JSON 내보내기/가져오기를 관리합니다. 가져오기는 현재 항목을 교체하고 모두 보류하므로 먼저 백업하세요.

## 기억 점검

개요의 **기억 점검** 카드에는 두 가지가 있습니다.

- **상시 진단(모델 호출 없음)**: 패널이 저장된 기억만 보고 바로 계산합니다. 같은 종류에서 날짜 표기를 뺀 내용이 같은 기억, 앞부분이 같은 기억(중복 의심), 빈 기억, 1,500자가 넘는 긴 기억, 날짜 표기(`[…]`)로 시작하지 않는 기억, 승인했지만 비공개라 주입되지 않는 기억, 공개지만 보류·재검토로 멈춘 기억, 검토 대기 후보 수, 자동 분석의 마지막 실패 이유를 보여 줍니다. 줄을 펼쳐 기억 이름을 누르면 해당 탭에서 그 기억이 열립니다.
- **기억 점검 (모델)**: 누르면 현재 기억과 최근 대화 원문을 설정 탭의 분석 모드·모델 연결로 보내 **중복, 서로 모순되는 기억, 이미 해소된 상태, 지켜진 약속, 너무 긴 기억**을 찾게 합니다. **누르는 즉시 전송되니, 비밀이 담긴 대화가 있는 채팅에서는 주의하세요.**
  - 보내는 것: 비밀·인물 제한·조건·보류(분기 보류·가져온 범위 보류·재개 필요 포함) 기억과 잠긴 위키를 뺀 기억(짧은 번호 `M1`, `M2`…로 바꿔 보내며 저장 ID는 보내지 않음)과 최근 대화 최대 40개(숨김 메시지 포함). 합쳐서 60,000자 한도 안에서 오래된 대화부터 뺍니다. 기억만으로 한도를 넘으면 호출하지 않고 안내합니다. 루미버스 요약 참고(기본 꺼짐)를 켰다면 남는 한도 안에서 이 채팅의 요약도 참고용으로 덧붙입니다(완료·보관은 요약만으로 판단하지 않게 지시).
  - 받는 것: **고쳐 쓰기**(중복 합치기·모순 바로잡기·압축), **완료로**(약속·진행 흐름만), **보관**(보류로 처리해 주입만 멈춤)만 받습니다. 새 기억 추가·삭제 제안, 보낸 번호에 없는 대상, 같은 대상에 대한 두 번째 제안은 버리고 개수를 알려 줍니다. 제안은 최대 30개이며, 응답 해석·2MB 크기·위험 키 검사는 분석과 같습니다.
  - 적용: 제안은 체크 목록으로 보이고(기본은 모두 체크), **체크한 제안 적용**을 눌러야 반영됩니다. 고쳐 쓰기는 변경 전·후를 함께 보여 줍니다. 점검한 뒤 그 기억이 바뀌었거나 지워졌거나 잠금·보류·비밀 등으로 바뀌었으면 ‘충돌’로 표시하고 체크할 수 없으며, 적용 순간에도 다시 확인해 건너뜁니다. 잠긴 위키는 후보 승인과 마찬가지로 점검 제안으로도 바꾸지 않습니다. 적용은 되돌리기 한 단계로 기록되고, 기억을 지우지 않습니다.
  - 점검 결과는 기억 데이터와 별도로 저장되어 새로고침해도 남고, **점검 결과 닫기**로 버립니다. 점검 자체는 기억 데이터나 되돌리기 기록을 바꾸지 않습니다.

## 루미버스 기본 요약과 함께 쓰기

**Summary (요약, Loom Summary)** 는 현재 이야기 전체의 개요 한 개를 저장하고 `{{loomSummary}}`로 전달합니다. 기억 보관함은 승인한 약속·기억 앵커·장면 등 세부 기억을 생성 직전 interceptor로 넣습니다. **서로 대체하지 않으며 함께 사용할 수 있습니다.** 기본 Summary에는 임베딩이 필요하지 않습니다.

1. 채팅을 선택하고 오른쪽 사이드바의 **Summary (요약)** 패널을 엽니다. **Settings (설정) → Embeddings (임베딩)** 메뉴가 아닙니다.
2. **Summarization Mode (요약 모드)** 에서 **Manual (수동)** 또는 **Automatic (자동)** 을 선택합니다.
3. **API Source (API 소스)** 를 펼쳐 **Active Connection (활성 연결)** 또는 **Dedicated Connection (전용 연결)** 을 선택합니다. 전용 연결을 고르면 사용할 모델 연결도 지정합니다.
4. **Manual Context (수동 컨텍스트) → Messages to include (포함할 메시지 수)** 를 정합니다. 자동 모드에서는 **Auto Settings (자동 설정)** 의 **Interval (간격)**, **Context (컨텍스트: 포함할 메시지 수)**, **Message lag (메시지 지연: 최근 제외할 메시지 수)** 도 정합니다. 새 메시지 일부를 남겨 두면 아직 바뀔 수 있는 장면이 곧바로 요약되는 것을 피할 수 있습니다.
5. **Summary Text (요약 텍스트)** 아래 **Generate (생성, 재생 모양 아이콘)** 로 요약을 생성하고 내용을 검토·수정한 다음 **Save (저장, 디스크 아이콘)** 합니다. 모델 호출 없이 직접 작성해 저장해도 됩니다. Generate는 선택한 LLM 연결을 호출하므로 비용·전송 범위를 확인하세요.
6. **활성 프리셋의 켜진 system 블록에 `{{loomSummary}}`를 추가합니다. 보통 Chat History (채팅 기록) 앞에 둡니다. 이 단계를 빼면 저장한 요약이 모델에 전달되지 않습니다.** 매크로 자체는 요약을 생성하지 않으며, 저장된 요약이 없으면 빈 값입니다. **Prompt Breakdown (프롬프트 분석) / dry-run (미리보기)** 에서 실제 해석된 내용을 확인하세요.

### 분석할 때 루미버스 요약 참고 (선택, 기본 꺼짐)

이 설정은 **기본으로 꺼져 있으며, 직접 켤 때만 동작합니다.** 켜지 않으면 기억 보관함은 루미버스 요약을 모델에 보내지 않습니다. 설정 탭의 **루미버스 요약(Loom) 참고 (선택)** 을 켜면, 기억 보관함이 모델을 부를 때(**분석**의 범위마다, **자동 분석**, **기억 점검**) 루미버스가 이 채팅에 저장해 둔 요약을 원문 뒤에 **참고용 블록**으로 따로 붙여 보냅니다. 요약은 채팅 정보에 함께 저장되어 있어 기존 `chats` 권한으로 읽으며, 새 권한이 필요하지 않습니다. 설정은 모든 채팅에 공통이고 기억 데이터나 되돌리기 기록에 영향을 주지 않습니다. 0.3.2에서 이 설정을 직접 켜거나 끈 적이 없다면 0.3.3부터는 꺼진 상태입니다. 계속 쓰려면 설정 탭에서 다시 켜세요.

- **역할**: 요약은 이야기 속 날짜·이름·앞뒤 흐름을 파악하는 데만 씁니다. 후보는 **고른 원문 범위에 실제로 나온 내용에서만** 뽑게 하고, 요약에만 있는 내용은 후보로 만들지 않게 합니다. 요약과 원문이 다르면 원문을 따르게 합니다. 기억 점검에서도 완료·보관은 최근 대화 원문에 근거가 있을 때만 제안하게 합니다. 요약 블록이 실제로 들어갈 때만 이 지침을 덧붙이며, 요약이 없으면 전송 내용은 이전과 같습니다.
- **한도**: 요약도 60,000자 입력 한도에 포함됩니다. **원문을 먼저 채우고 남는 한도만** 요약에 쓰므로 요약 때문에 원문이 빠지거나 분석이 실패하지 않습니다. 요약은 최대 8,000자이며, 넘거나 남는 한도가 부족하면 **앞부분을 잘라 뒷부분을 남깁니다**. 루미버스 요약은 항목별 정리라서 잘릴 때는 앞쪽 항목(예: 이미 끝난 일)부터 빠집니다. 남는 한도가 너무 적으면 요약을 빼고 원문만 보냅니다.
- **표시**: 분석 탭의 범위 요약 줄에 ‘대화 120–141 (22개) · 루미버스 요약 참고 (1,234자)’ 또는 ‘요약 없음’이 붙습니다(최대로 보낼 양이며, 원문이 길면 실제로는 더 줄 수 있음). 분석·기억 점검·자동 분석 결과 줄에는 실제로 보낸 글자 수가 남습니다.
- **안전**: 요약 내용은 신뢰하지 않는 자료로 다룹니다. 문자열이 아니거나 2MB를 넘으면 없는 것으로 보고, 제어 문자와 블록 표시를 지운 뒤 넣으며, 지시가 아닌 자료로만 읽게 합니다. 요약 내용은 기억·후보·근거·설정 어디에도 저장하지 않습니다. 후보의 근거는 항상 원문 메시지입니다.
- **주의**: 요약에는 고른 범위 밖의 대화 내용도 담겨 있습니다. **요약에 비밀이 들어 있다면 이 설정을 켜지 마세요.** 이미 켰다면 끄면 바로 보내지 않습니다.

선택 사항인 **Chat Memory / LTM (장기 채팅 기억)** · **Memory Cortex (메모리 코어텍스)** 는 임베딩을 사용하는 별도 회상 계층입니다. 여기서는 필수가 아닙니다. 요약과 기억 보관함에 같은 내용을 중복 저장하면 같은 내용으로 토큰을 두 번 쓸 수 있습니다.

## 원본과의 차이 · 미지원 기능

**원작의 탭 구성과 흐름을 따른 루미버스용 간소화 화면**입니다. 원본 CSS와 일곱 탭의 순서, 개요 → 목록/상세 → 편집 → 후보 검토 흐름을 따르지만 원작 UI 전체를 복원한 것은 아닙니다. Lumiverse 서랍 안에 표시하므로 원본의 독립 모달·현재 이야기 선택기는 호스트의 채팅 전환과 서랍 닫기로 대체합니다. 좁은 서랍에서는 목록과 상세가 위아래로 쌓이고 탭은 줄바꿈됩니다. 색·입력칸·버튼은 Lumiverse 테마를 따릅니다.

다음은 베타의 한계이며 작동하지 않는 원본 설정·버튼으로 흉내 내지 않습니다.

- 인물 매핑·인물별 비밀 주입: 미구현. 인물 제한은 주입 보류합니다.
- 주입 예산·키워드 조건 호출: 미구현. 승인된 무조건 공개 항목만 주입합니다.
- 흐름별 상태 이력·구조화 장면·요소 조건 검색·위키 목차/자동 갱신: 미구현. 해당 탭은 텍스트 중심의 목록/상세/수동 편집입니다.
- 원작 위키의 분류 사이드바·분류 격자와 상세 상태 세그먼트·정보 격자는 제공하지 않습니다. 약속·진행 흐름의 상태는 간단한 필터와 버튼으로 다룹니다. 위키·앵커·장면·요소에는 약속용 상태 조작을 표시하지 않습니다.
- 원본 Marinara/SillyTavern JSON 변환기: 미구현. 이 확장의 JSON 형식만 가져옵니다.
- 로어북 동기화·Keeper: 미지원. 로어북 동기화 대신 생성 직전 직접 주입을 사용합니다. 자동 분석은 아래 ‘자동 분석’처럼 후보 만들기까지만 하고, 승인은 항상 사람이 합니다.

## 주입과 비밀 보호

실제 생성의 채팅 ID와 인증된 사용자로 저장분을 조회합니다.

**신뢰 경계:** 생성 문맥의 사용자·채팅 ID는 다른 확장의 context handler가 바꿀 수 있으므로 그대로 믿지 않습니다. 호스트가 실제 생성 채팅에서 조립해 원문 메시지 ID를 표시한 대화 기록이 모두 그 채팅에 속하고, 그 채팅이 해당 사용자 소유일 때만 주입합니다. 확인할 수 없으면 기억 없이 생성합니다. **기억을 넣지 못하는 생성:** 프리셋의 메시지 합치기(collapse messages)처럼 대화 기록을 메시지 하나로 다시 만드는 설정, 대화 기록이 하나뿐인 채팅에서 그 메시지를 이어쓰기(continue)하는 경우, 대화 기록을 넣지 않는 프리셋, 빈 채팅입니다. 이때는 조용히 넘어가지 않고 채팅마다 한 번 경고 알림을 띄우며, 개요의 ‘최근 답변’ 줄에 ‘기억을 넣지 못했습니다’로 남깁니다. 공개 기억이 없다고 확인된 채팅에는 알림을 띄우지 않습니다. ‘최근 답변’ 표시는 서버를 다시 시작하면 비워집니다. 이 확인은 Lumiverse 1.2.5의 원문 메시지 ID 표시 동작에 기대며, 다른 확장이 서버 전체 권한으로 저장소를 직접 읽는 경우까지 막지는 못합니다. 비밀·알 수 없는 범위·인물 제한·조건·보류·분기 보류·재검토·가져온 범위·재개 필요 항목은 주입하지 않습니다. 원문 근거를 매번 다시 확인합니다. 공개 확인 체크 하나로 모든 제한이 자동 해제되지는 않습니다.

권한 부족·읽기 실패·시간 초과에는 기억 없이 원래 생성을 진행하는 optional(fail-open) interceptor입니다. 분기는 원문 위치·내용·새 UUID 및 호스트가 기록한 편집 시각을 비교합니다. 분기 뒤 편집·부모 소실·시각/근거 부족은 보류합니다. undo는 원래 출처를 유지합니다. 잠긴 위키 변경과 보류 후보 승인은 거절합니다.

**월드북(World Book, 로어북)을 만들거나 연결하지 않고 생성 직전에 system 메시지 하나로 직접 넣습니다.** 각 항목은 `약속: 내용`, `기억 앵커: 내용`처럼 한국어 종류와 본문만 전달합니다. 확장 이름·헤더·내부 영어 종류 ID·저장 파일명·채팅명·캐릭터명을 별도 메타데이터로 덧붙이지 않습니다. 다만 사용자가 기억 본문에 직접 쓴 이름까지 삭제하지는 않습니다.

**과거 수동으로 내보내거나 연결한 책은 자동 삭제하지 않습니다.** 그 책은 호스트에서 직접 연결 해제·삭제해야 합니다.

## 자동 분석 (기본 꺼짐)

**사용자 메시지 N개마다** 새로 쌓인 대화를 자동으로 분석해 검토 대기에 후보로 넣는 기능입니다. **기본값은 꺼짐**이며, 채팅마다 따로 켭니다.

- **켜는 법**: 설정 탭에서 분석 모드와 모델 연결을 먼저 고른 뒤, ‘자동 분석’ 카드의 **사용자 메시지 N개마다 자동 분석**을 체크하고 간격 N(기본 10, 3–100)을 정해 **자동 분석 저장**을 누릅니다. 모델 연결을 고르지 않으면 켤 수 없습니다. 켤 때 고른 모드·연결이 이 채팅의 자동 분석에 저장됩니다.
- **무엇을 보내나**: **켠 시점부터 셉니다.** 그 이전 대화는 자동으로 보내지 않습니다. 마지막 자동 분석(또는 켠 시점) 뒤에 사용자 메시지가 N개 쌓이면, 답변 생성이 끝난 뒤 **그 뒤의 대화 원문 전체(사용자·캐릭터 메시지, 숨김 메시지 포함)** 를 고른 연결로 자동 전송합니다. 비밀이 담긴 대화를 나눌 채팅에서는 켜지 마세요. 루미버스 요약 참고(기본 꺼짐)를 켰다면 이 채팅의 요약도 남는 한도 안에서 함께 보냅니다.
- **세는 기준**: 채팅에 실제로 저장된 사용자 메시지만 셉니다(숨긴 사용자 메시지도 셉니다). 스와이프·재생성은 기존 답변의 다른 버전이라 개수를 늘리지 않으며, 연달아 일어난 생성은 잠시 모았다가 한 번만 확인합니다. 사칭(impersonate)·실패한 생성은 계기로 쓰지 않습니다.
- **답변을 막지 않음**: 확인과 모델 호출은 답변이 끝난 뒤 따로 돌며, 다음 답변의 기억 주입을 기다리게 하지 않습니다. 같은 채팅에서는 한 번에 하나만 실행합니다.
- **입력 한도**: 한 번에 60,000자까지 보냅니다. 넘으면 **가장 최근 메시지부터 한도 안에 들어가는 만큼만** 분석하고, 앞쪽 생략 개수를 결과 줄에 남긴 채 다음 구간으로 넘어갑니다. 메시지 하나가 한도를 넘으면 그 구간은 건너뛰고 실패로 표시합니다. 빠진 구간은 분석 탭에서 범위를 골라 직접 분석할 수 있습니다.
- **결과**: 후보는 검토 대기에만 들어가며 **자동 승인하지 않습니다.** 모델이 정한 공개 범위도 쓰지 않고 모두 ‘알 수 없음’으로 받습니다. 응답 해석·크기·위험 키 검사·후보 정규화·소유권 확인은 수동 분석과 같습니다. 개요에 ‘자동 분석: 마지막 실행 HH:mm · 후보 N개’ 또는 실패 이유가 표시됩니다.
- **실패하면**: 이유를 개요에 남기고 바로 다시 시도하지 않습니다. 사용자 메시지가 N개 더 쌓이면 마지막 성공 지점부터 다시 분석합니다.
- **끄거나 다시 켜면**: 끄는 순간부터 아직 모델에 보내지 않은 자동 분석은 보내지 않습니다. 이미 보낸 호출은 취소하지 못하지만, 끄거나 껐다 다시 켠 뒤 돌아온 예전 결과는 후보로 넣지 않고 분석 위치도 바꾸지 않습니다(다시 켠 시점 이전 대화를 자동으로 다시 보내지 않음). 모델 연결·모드를 바꾼 경우에도 아직 보내지 않은 분석은 새 설정으로 다시 준비합니다.
- **위치 저장 실패**: 후보는 저장했는데 마지막 분석 위치를 저장하지 못하면 성공으로 표시하지 않고 이 채팅의 자동 분석을 **멈춤**으로 표시합니다. 같은 구간을 다시 보내지 않으며, 다음 답변 때 위치 저장을 다시 시도하거나 설정 탭에서 **자동 분석 저장**을 다시 누르면 다음 구간부터 이어서 셉니다. 서버를 다시 시작해도 이미 저장된 자동 분석 후보가 덮는 구간은 다시 보내지 않습니다(그 후보를 지웠다면 예외).
- **저장 위치**: 자동 분석 설정·마지막 분석 위치·결과는 기억 데이터와 별도로 저장되어, 켜고 끄는 것이 되돌리기 기록이나 기억 데이터에 영향을 주지 않습니다. 자동 분석으로 들어온 후보는 수동 분석처럼 되돌리기 한 단계로 기록됩니다.

## 분석 · 권한

raw와 quiet 모두 설정에서 고른 명시적 연결만 사용합니다. 분석 요청에는 범위 번호만 담기며, 원문은 서버가 호스트에서 직접 읽어 범위를 다시 검증한 뒤 보냅니다. raw는 선택한 연결에 지정된 모델로 호출하며, 모델이 지정되지 않은 연결은 호출하지 않고 오류를 표시합니다(모델 목록에 ‘(모델 미지정)’ 표시). quiet는 연결의 프리셋 설정을 사용합니다. 모델 응답이 이미 올바른 JSON이면 그대로 쓰며, 문자열 속 `<think>` 같은 글자도 지우지 않습니다. 그렇지 않을 때만 앞쪽 추론 블록·코드 펜스(```json)·앞뒤 설명을 건너뛰고 가장 바깥 JSON 값을 찾습니다. 그 값이 잘렸으면 안쪽에 있는 다른 배열로 대신하지 않고 실패하며, 응답 앞부분과 함께 다시 시도를 안내합니다. 응답 원문이 2MB를 넘으면 해석하지 않습니다. 객체로 감싼 배열(`{"candidates":[...]}` 등)·한국어 종류 이름·대소문자/단복수·`content`/`summary`/`memory` 키·앞뒤 공백은 맞춰 읽고, 그래도 쓸 수 없는 항목만 건너뛰어 “N개 중 M개 형식 오류로 제외(예: …)”로 알립니다. 모델이 정한 공개 범위는 쓰지 않고 모든 후보를 ‘알 수 없음’으로 받으며, 공개 여부는 승인할 때 사람이 정합니다.

분석 입력의 각 메시지 앞에는 전송 시각(`[전송 2026-10-18 19:10]`, 브라우저 시간대 기준이며 알 수 없으면 UTC로 표시)을 붙이고, 지침은 후보마다 이야기 속 날짜·시각(`[이야기 2일차 저녁]`)이나 없으면 기록 시각(`[기록 2026-10-18 19:10]`)을 앞에 남기고 ‘어제·오늘’ 같은 상대 표현을 절대 날짜로 바꾸게 합니다. 이 표기도 60,000자 입력 한도에 포함됩니다. 연결 설정 자체는 고정하지 않으므로 연결 설정 변경이나 model roulette이 실제 모델을 바꿀 수 있습니다. 분석 전에 보낼 입력을 따로 보여 주지 않으니, 원문에 비밀이 포함될 범위는 고르지 마세요.

| 권한 | 용도 |
|---|---|
| `chats` | 채팅 조회·소유권 검사, 루미버스 요약(채팅 메타데이터) 읽기 |
| `chat_mutation` | 원문 조회·근거 확인·기억 점검의 최근 대화. 메시지 수정 API는 호출하지 않음 |
| `generation` | 모델 연결 목록(이름·모델) 조회, 사용자가 누른 분석·기억 점검과 켜 둔 자동 분석, 자동 분석 계기인 생성 완료 이벤트 수신 |
| `interceptor` | 생성 직전 공개 기억 주입 |

외부 네트워크·파일·환경변수·World Book 권한은 요청하지 않습니다. 선택 모델 호출은 호스트의 generation API를 통합니다. 사용자 텍스트를 HTML로 실행하거나 이미지 URL을 가져오지 않습니다.

## 저장 · 백업 · 제거

사용자별 채팅 저장소에 현재 데이터와 직전 백업을 보존합니다. revision 검사·사용자/채팅별 큐를 사용하지만 다중 worker의 원자 CAS는 보장하지 않습니다. 저장 응답 유실 시 재전송하지 말고 새로고침해 확인하세요.

JSON 백업에는 **비밀과 후보도 포함**됩니다. 공개 장소에 올리지 마세요. 가져온 데이터는 모두 보류됩니다. 최대 20회 undo, 요소 400개·위키 후보 40개·전체 2,000개 및 UTF-8 JSON 2,000,000바이트 제한을 적용합니다. 용량 부족 시 오래된 undo부터 줄이고 현재 기억·후보는 자동 삭제하지 않습니다. 본문 자체가 가득 차면 내보내기 후 불필요한 항목 삭제·텍스트 축소가 필요합니다. 보류는 주입을 막을 뿐 용량을 줄이지 않습니다.

읽을 수 없는 저장분은 새로고침 후 복구 확인을 거쳐 직전 백업 복원 또는 초기화합니다. 교체 전 데이터는 복구본에 보존하고 직전 백업은 유지합니다. 반복 복구는 복구본을 덮어쓸 수 있습니다. JSON 자체가 아니거나 저장소가 쓰기 불가능하면 호스트 측 수동 복구가 필요합니다.

비활성화하면 새 주입이 멈추고 데이터는 남습니다. 제거 전 JSON을 내보내세요. 제거 시 호스트가 확장 저장소를 삭제할 수 있습니다.

## 개발 검증

Node.js 22 이상과 npm을 권장합니다. DOM 테스트용 `linkedom`을 고정했습니다.

```sh
npm ci
npm test
npm run build
npm run qa
```

소스가 바뀌면 같은 커밋에 재빌드한 `dist/`를 포함해야 합니다. 깨끗한 clone의 재빌드는 추적된 실행물과 바이트가 같아야 합니다. 호스트·브라우저 QA는 합성 데이터와 가짜 공급자로 수행하며 실모델 호출 결과를 의미하지 않습니다.
