# 기억 보관함 — Lumiverse (1.0.0-rc.1)

채팅별 약속·진행 흐름·기억 앵커·장면 기억·요소 기억·이야기 위키를 관리하는 **비공식 Spindle 확장**입니다. 1.0부터는 **원작자가 만든 Marinara 확장 「기억 보관함 v2.1.1」을 한 글자도 고치지 않고 그대로** 실행하고, 이 저장소의 코드는 그 원본이 루미버스에서 돌도록 이어 주는 **얇은 어댑터**만 담습니다.

**Lumiverse 및 Marinara Engine의 공식 확장이 아니며, 해당 팀이 제작·승인·보증·지원하지 않습니다.** Not affiliated with, endorsed by, or supported by Lumiverse or Marinara Engine or their creators.

## 출처와 허가

이 확장의 화면과 기억 처리 로직은 전부 [원 게시글 작성자의 Marinara 「기억 보관함」 v2.1.1](https://m.dcinside.com/mini/aichatfrontend/162)입니다. 이 저장소는 그 원본의 소유자가 아니며 원본을 자기 것이라고 주장하지 않습니다. 원 게시글 작성자는 **2026-10-06** 댓글에서 SillyTavern 이식을, **2026-10-16 15:56** 댓글에서 Lumiverse 버전 제작·수정을 허락했습니다. 원작자가 직접 배포한 Lumiverse판은 아닙니다. 라이선스 근거와 고지문은 `NOTICE`에 있습니다(저장소 자체의 라이선스는 AGPL-3.0-only).

- 원본 파일은 `vendor/original/`에 **바이트 그대로** 두고, 빌드 때마다 SHA-256 핀(`scripts/verify-original.mjs`)과 대조합니다. 다르면 빌드가 멈춥니다.
- 핀(SHA-256): `extension.js` `a183f7243c801f10b9841ec5ebecb62ecdfe21119f20f29dab6cfcb7f410c089`, `extension.css` `34de20009edf869f7af1d85ba88045118426d091b7dc5458d4cec19add1fa9f7` (작성자 zip `21c2dab541196098f12b76eb2440257210434a3d1548006ff87ca220e1280c79` 안의 파일). 원본 zip 자체는 저장소에 넣지 않습니다.
- 빌드가 원본에 하는 일은 하나뿐입니다. 호스트 이름이 사용자에게 보이는 문구 3곳(`src/text-map.json`: 「Marinara 경로」「summaryEntries」「마리나라 테마 따르기」)을 루미버스 용어로 바꿉니다(바꾼 횟수까지 검사). 원본은 이미 한국어라 번역 계층은 없습니다.

## 0.4.x에서 달라진 점 (꼭 읽어 주세요)

0.4.x는 원본을 참고해 **새로 짠 코드**였고, 1.0은 원본을 **그대로 쓰는** 방식입니다. 그래서 화면·동작이 원본 v2.1.1과 같아지고, 0.4.x에만 있던 기능은 사라집니다.

### 없어진 기능

장면록·구간 연대기, 메시지 번호 범위 분석(및 60,000자 자동 나누기), 옛 「사용자 N턴마다」 자동 분석 상태기계(영수증·일시정지·백오프), 루미버스 요약(Loom) 분석 첨부, 일괄 선택·전체 삭제, JSON 내보내기/가져오기·되돌리기(undo) 20회, 생성 직전 interceptor 직접 주입, 공개 범위 승인 게이트, 상시 진단 일부, 20개씩 더보기 컴팩트 목록. 이 중 원본에도 같은 목적의 기능이 있는 것(로어북 동기화·자동 적용 1회 되돌리기·건강검진)은 원본 방식으로 쓰게 됩니다. 기억은 interceptor가 아니라 **채팅 전용 로어북**으로 프롬프트에 들어갑니다.

### 업그레이드 (식별자 `memory_cabinet` 유지 — 같은 자리에서 교체됩니다)

1. 업데이트하면 확장 목록의 같은 항목이 1.0.0-rc.1로 바뀝니다. 필요한 권한은 `chats`, `chat_mutation`, `generation`, `world_books`, `characters` 5개이며 `interceptor`는 더 이상 쓰지 않습니다.
2. 옛 데이터(0.4.x가 남긴 기억)가 있으면 채팅을 열 때 **「0.4.x 데이터 옮기기」 화면이 저절로 뜹니다**(Extras 메뉴의 「기억 보관함 설정」으로도 열 수 있어요).
   - **① 백업 받기** — 옛 데이터 전부(항목·후보·되돌리기·자동 분석 기록·설정)가 든 JSON 파일을 내려받습니다. 파일이 안 받아지는 환경(일부 앱 내 브라우저)에서는 **「텍스트로 보기」**로 글을 복사해 메모 앱에 붙여 두세요. 보안 연결이 아닌 http 접속·휴대폰에서도 동작하도록 만들었습니다.
   - **「백업을 저장했어요」** 체크 후 **② 약속·앵커 가져오기** — 깔끔하게 옮길 수 있는 **약속·앵커만** 원본 형식으로 가져옵니다. 이미 원본 데이터가 있는 채팅은 건드리지 않습니다.
   - 공개 범위가 정해지지 않은 항목·인물 제한이 있는 항목은 **보존하되 주입하지 않거나 같은 제한 그대로** 들어옵니다(가져오기가 비밀을 공개로 바꾸는 일은 없습니다).
   - 장면록·요소·흐름·위키·검토 후보·되돌리기·자동 분석 기록은 **백업 파일에만** 남습니다. 옛 장면록 로어북은 지우지 않고 그대로 둡니다.
   - 가져오기를 건너뛰고 새로 시작해도 됩니다(「다시 묻지 않기」).

## 자동 분석

원본의 자동 분석은 「새 요약이 생기면 그 요약을 분석한다」는 방식입니다. 루미버스에는 그런 요약이 없으므로 어댑터가 **사용자 턴 N개마다 그 구간의 대화 원문을 요약 1건으로 만들어 넘깁니다**(별도 요약 모델 호출 없음). 그러면 원본이 자기 방식 그대로 분석 → 후보 → 승인 → 로어북 순서로 처리합니다.

- N은 Extras 메뉴 → **기억 보관함 설정**에서 정합니다(3~100, 기본 10). 채팅별 턴 수는 저장소에 보관되어 재시작해도 이어집니다.
- **기본은 꺼져 있습니다.** 기억 보관함 설정(원본 화면)의 **「새 요약 갱신 방식」**을 「자동 분석 후 승인 대기」 또는 「완전 자동 적용(실험적)」으로 바꾸고 모델 연결을 골라야 돕니다. 모델 API 비용이 생깁니다.
- 분석이 실패하면 다음 N턴째에 쌓인 구간과 함께 다시 시도합니다(재시도 상태기계는 없음).
- 합성 「요약」은 진짜 요약이 아니라 **최근 N턴의 대화 원문**이므로 호출당 토큰이 원본 설계보다 큽니다. 이미 N턴이 넘은 채팅은 설치 시점부터 새로 세고, N턴보다 짧은 채팅은 첫 메시지부터 셉니다.
- 탭을 여러 개 열어 두어도 트리거는 한 탭만 처리합니다(서버가 먼저 요청한 탭 하나만 통과시킴).
- **원본은 브라우저 안에서 돕니다.** 그 채팅을 보고 있는 탭이 하나도 없을 때 N턴이 지나면 그 구간은 분석되지 않고 건너뜁니다(다음 N턴부터 다시 셈). 분석을 서버가 대신 돌려 주지 않습니다.

## 한계 (알고 쓰세요)

- **인물별 비밀(아는 사람 제한)**: 루미버스 로어북에는 인물 필터가 없어 항목 본문을 `{{if::{{char}}==이름}}…{{/if}}`로 감싸 저장합니다(원본 화면에는 원문이 그대로 보임).
  - 이름이 맞는 인물의 차례에만 보입니다. **캐릭터 이름을 바꾸면 깨집니다**, 동명이인은 구분하지 못합니다, 이름에 `}}`가 들어 있으면 위험합니다.
  - 그룹 채팅: 교대(swap) 모드는 실제 호스트 미리보기(dry-run, 대상 인물 지정)에서 허용 인물에게만 보이는 것을 확인했습니다. **합치기(merge) 모드**도 같은 방식의 미리보기에서는 같게 나왔지만, 여러 인물을 합쳐 생성하는 실제 경로에서 `{{char}}`가 어떻게 풀리는지는 확인하지 못했으므로 새거나 빠질 수 있다고 보세요. 개별 비밀이 중요한 그룹 채팅에서는 합치기 모드를 쓰지 마세요.
  - 제한 항목은 로어북 편집기에서 조건문 래퍼가 그대로 보이고, 비허용 인물 차례에도 빈 내용으로 순서·예산 자리를 차지합니다.
- **분기(branch) 채팅**: 호스트가 부모의 메타데이터를 복사해 옵니다. 원본이 분기를 감지해 소유자를 분리하고 부모 전용 로어북을 떼어 냅니다(실제 호스트에서 확인). 분기 직후 한 번 보관함을 열거나 채팅을 열어야 분리됩니다.
- **메타데이터 쓰기 경합**: 루미버스 확장 API에는 메타데이터 병합이 없어 읽고-합치고-쓰기를 합니다. 같은 채팅에 대한 우리 쓰기는 순서대로 처리하고, 쓰기 직전에 다시 읽고, 쓴 뒤 확인해서 덮어써졌으면 다시 씁니다. 호스트의 백그라운드 쓰기가 읽기와 쓰기 사이(수 ms)에 끼면 그 쓰기를 잃을 수 있습니다.
- **채팅 전환**: 원본은 자기가 고른 채팅의 요약만 자동 처리하므로, 루미버스에서 채팅을 옮기면(보관함을 닫은 상태에서) 원본을 다시 띄워 지금 채팅을 고르게 합니다. 보관함이 열려 있는 동안에는 건드리지 않고 닫은 뒤 옮깁니다.
- **확인 창(`confirm`)**: 원본은 삭제·되돌리기 등에서 브라우저 확인 창을 씁니다. 창이 막힌 환경(일부 휴대폰·앱 내 브라우저)에서는 눌러도 아무 일도 안 되는 것처럼 보이므로, 이를 감지하면 「같은 버튼을 한 번 더 누르면 실행돼요」 안내를 띄우고 6초 안에 같은 버튼을 다시 누르면 실행합니다. 호스트의 확인 창은 건드리지 않습니다.
- **화면 색**: 원본 화면은 밝은 팔레트(리본 라일락·스토리 로즈·아카이브 그린)이고, **루미버스 테마 따르기**를 고르면 현재 루미버스 테마(밝음/어두움)를 따라갑니다. 휴대폰용으로 글자 크기(본문 15px·보조 13px 이상)·터치 크기(44px)·대비(4.5:1)를 `src/overrides.css`로 보정했습니다.
- 서로 신뢰하지 않는 여러 사용자가 한 서버를 함께 쓰는 환경은 지원하지 않습니다.
- 호스트: 루미버스 main(2026-10-24, spindle-types 0.6.49)과 staging 양쪽에서 확인했습니다. 임시 인스턴스는 Bun 1.4.3으로 돌렸습니다(main은 1.4.4를 요구해 임시 사본의 최소 버전 검사만 낮춤).

## 개발 · 검증

```
node scripts/verify-original.mjs      # 원본 핀 대조
BUN_BIN=~/.bun/bin/bun node scripts/build.mjs   # 핀 대조 → 문구표 적용 → dist/ 번들(원본은 vendor/ 그대로)
npm test                              # 단위·계약 테스트(원본 핀, 어댑터, 이전, 매니페스트 권한, 번들 금지 API)
node scripts/browser-qa.mjs           # 다뷰포트·테마·비보안 http·Firefox/Chromium 브라우저 QA (PLAYWRIGHT_MODULE 등 환경변수 필요)
LUMI_SRC=… PORT=7895 … node qa/e2e-host.mjs   # 임시 루미버스 인스턴스 e2e(가짜 LLM)
```

어댑터 구성(`src/`): `backend.js`(라우트·트리거·이전) · `host.js`(원본이 부르는 `/api/*` → 루미버스 API 번역, 메타데이터 쓰기 보호) · `router.js` · `trigger.js`(N턴 트리거) · `shim.js`(`window.marinara`·`fetch` 번역, 탭 클레임) · `frontend.js`(채팅 전환 추적) · `panel.js`(설정·이전 화면) · `confirm-guard.js` · `host-theme.js` · `migrate.js` · `download.js` · `overrides.css` · `text-map.json`. 원본이 쓰는 `/api/*` 호출은 테스트가 원본 소스에서 뽑아 라우터와 대조합니다.
